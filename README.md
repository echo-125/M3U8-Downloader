# M3U8下载器

用 Rust 重写的 M3U8 视频下载器，Windows 桌面图形界面，发布形态为便携版单 exe。

本项目由 Python 版完全重构而来，目标是在保持功能等价的前提下降低内存占用、提升启动速度与运行稳定性。

## 环境要求

- 操作系统：Windows 10 及以上，x64
- Rust：stable
- 图形框架：`egui` / `eframe`
- 仅支持中文界面

## 功能

- 单个任务添加、批量添加、手动合并本地分片
- 多任务并行下载与队列自动调度
- 分片级断点续传，程序重启后自动继续未完成任务
- 任务取消、重试、删除，清除已结束任务
- 任务列表可多选（点击行或勾选框），批量开始、取消、重试、删除
- 任务筛选（全部 / 进行中 / 已完成 / 已失败）与文件名搜索
- 任务状态（带颜色与形状标识）、进度、下载速度与剩余时间展示，进度条悬停看分片数
- 右键菜单与双击快捷操作，菜单项按任务状态禁用
- 自定义请求头
- 剪贴板粘贴，支持 `链接|文件名|请求头JSON` 增强格式
- 亮色 / 暗色主题，状态持久化
- 系统托盘：关闭窗口最小化到托盘，托盘可恢复窗口与退出
- 全部任务结束时汇总提示（窗口在托盘则自动恢复）
- 失败与完成 Toast 提醒，错误提示常驻直到手动关闭
- 设置面板、GUI 日志面板（可折叠）与文件日志
- 全局代理（HTTP / HTTPS / SOCKS5，支持认证）
- 尾部加速，阈值与并发倍数可配置

## M3U8 支持范围

支持：

- VOD 点播播放列表
- 主播放列表递归解析，自动选择最高带宽变体
- AES-128 CBC 解密，支持显式 IV、基于 `MEDIA-SEQUENCE` 的隐式 IV 与 key rotation
- TS 分片
- fMP4 / CMAF 分片，含 `EXT-X-MAP` 初始化段与初始化段 `BYTERANGE`
- 分片格式采样诊断

不支持：

- 直播流录制
- DRM
- SAMPLE-AES
- 非标准私有扩展的深度兼容

## 下载与重试策略

- 可配置最大并发任务数与单任务下载并发数
- 429 自动重试，优先尊重 `Retry-After`
- 5xx、网络错误与超时自动重试，最多 3 次
- 404、403 不自动重试，403 会提示检查防盗链或请求头
- 所有请求设置 30 秒总超时与 10 秒连接超时
- 下载失败默认保留临时文件；下载成功后默认自动清理，也可选择保留用于排查
- 解密失败不终止任务：保留原始密文到 `_debug` 目录供排查，完成后明确警告输出可能损坏

合并策略：

- TS 分片先二进制拼接，自动修剪首部混入的垃圾数据，再调用 ffmpeg remux 为 MP4
- fMP4 拼接前剥离分片的 `styp` box，拼接后用 ffmpeg 重封装并前置 moov 索引
- ffmpeg 流拷贝与重编码都失败时，降级为直接输出 TS，任务不会因此失败
- ffmpeg 默认从 PATH 自动检测，也可在设置中手动指定路径
- 未检测到 ffmpeg 时 TS 任务保留 TS 输出
- 输出文件重名时自动追加编号，不会覆盖已有文件

## 构建与运行

```powershell
# 调试运行
cargo run

# 发布构建，产物为 target\release\M3U8下载器.exe
cargo build --release
```

开发期常用命令：

```powershell
cargo fmt
cargo clippy --all-targets -- -D warnings
cargo test
```

发布产物为 Windows x64 便携版单 exe，不做代码签名、不做自动更新、不配置 CI/CD。

### 自动化测试

`cargo test` 共 58 项，全部本地运行、不访问外网。其中 `src/core/e2e_tests.rs` 是端到端测试：
启动一个监听 127.0.0.1 随机端口的极简 HTTP 服务器，喂入内存构造的 M3U8 与分片数据，
真实跑完「解析 → 下载 → 解密 → 合并」整条链路，再逐字节比对输出文件，最后校验进度事件流。

已覆盖：

- 普通 TS 播放列表下载，并按顺序合并
- AES-128 解密后合并，输出字节必须等于加密前的明文
- 主播放列表选取最高带宽变体
- 分片级断点续传：已落盘的分片不被重新下载
- 播放列表 404 时任务干净失败，且保留临时目录
- 取消（重置）保留 manifest，进度不丢失，可继续断点续传
- 任务临时目录被手动删除后再重置，行为正确
- 进度快照持续上报、单调递增、终态正确

未覆盖（依赖真实环境或外部程序，只能人工验证）：ffmpeg remux、代理、429 / 5xx 重试、
key rotation、fMP4 / CMAF。

## 配置与数据位置

| 内容     | 位置                                                                              |
| ------ | ------------------------------------------------------------------------------- |
| 配置文件   | 程序同目录 `config.json`，目录不可写时降级到 `%APPDATA%\cat-catch-assistant\config.json`       |
| 任务注册表  | 配置文件同目录 `tasks.json`                                                            |
| 日志文件   | 程序同目录 `logs\cat-catch.日期.log`，不可写时降级到 `%LOCALAPPDATA%\cat-catch-assistant\logs` |
| 临时分片   | 下载目录下的 `.cat-catch-tasks\<任务号>-<名称>\`                                           |
| 默认下载路径 | 系统下载目录                                                                          |

GUI 日志保留最近 500 条，显示在窗口底部的面板里，可点击标题栏的箭头折叠（默认折叠，状态会被记住）；
文件日志支持按天或按大小滚动。

代理密码以明文存放在 `config.json` 中，**不做加密**——这是有意为之，不是待办项：本程序是便携版单 exe，
加密所需的密钥无处安全存放，硬编码密钥只是把明文换了个地方。加密只能挡住「用记事本打开配置文件」这一种情况，
却会让配置损坏时无法手动修复。结论是保持明文，风险自负，请勿在不信任的环境填写代理密码。

## 目录结构

```text
src/
├── main.rs          # 入口，加载配置、初始化日志、启动窗口
├── app/             # egui 界面：layout 总装配、widgets 通用控件、
│                    # forms 表单、task_list 列表、dialogs 浮层、
│                    # state 状态、theme 主题、tray 托盘
├── core/            # M3U8 解析、下载、解密、合并、任务调度
│                    # e2e_tests 端到端测试（本地 HTTP 服务器，不联网）
├── config/          # 配置结构与持久化
├── logging/         # GUI 日志缓冲与文件日志滚动
└── ffmpeg/          # ffmpeg 检测与 remux
```

架构原则：下载核心不依赖 GUI，GUI 只通过命令、事件与状态快照与核心交互；所有网络请求设置超时；任务操作通过消息队列传递，不在界面线程执行阻塞 IO。

## 使用说明

1. 在任务创建区粘贴 M3U8 链接，选择保存路径与文件名，点击「添加任务」；也可点「粘贴」直接解析 `链接|文件名|请求头JSON` 格式。
2. 批量添加格式为每行一条：`链接|文件名|请求头JSON`，文件名与请求头可省略。
3. 任务列表中点击行或勾选框即可勾选，可多选，工具栏按钮对全部选中任务生效；右键可开始、取消、编辑、重试、删除、复制链接、打开目录。双击只对「等待中 / 已失败 / 已取消」的任务开始下载、对「已完成」的任务打开所在目录，下载中的任务双击不响应——取消请用工具栏或右键菜单。注意「取消」会删掉已下载的分片，见下方行为约定。
4. 「移除任务」有三个入口，作用范围与是否删本地文件各不相同，见下方「三个移除入口的区别」。
5. 手动合并页选择存放 TS 或 fMP4 分片的文件夹，先「扫描分片」再「开始合并」。合并输出写到该文件夹，
   不会删除其中任何分片，也不受「成功后自动清理」设置影响——那是针对下载任务的选项，手动合并操作的是
   用户自选的文件夹，程序不代做删除。
6. 关闭窗口会最小化到系统托盘，从托盘菜单可恢复窗口或退出程序；有下载中任务时退出需要确认。

## 行为约定

下面几条是有意设计，但和直觉容易冲突，单独列出来：

- **「取消」会删除已下载的分片**，任务回到「等待中」，不产生「已暂停」状态。取消后重新开始是从零下载，
  不保留断点续传。想保住进度就不要点取消——直接关闭程序或最小化到托盘都不会清除分片。
- **已完成的任务不能重新开始。** 对已完成任务再次「开始」会重置任务信息、重新下载并覆盖已有成品文件，
  所以界面不提供这个入口，核心侧也会拒绝（界面与核心是双保险）。确实需要重下，请先删除任务再重新添加。
- **代理密码明文存储、不做加密。** 理由见「配置与数据位置」。
- **解密失败不终止任务**：原始密文保留到临时目录的 `_debug` 子目录供排查，完成后会明确警告输出可能损坏。

### 三个移除入口的区别

界面上有三个都会让任务从列表消失的操作，语义并不相同：

| 入口 | 作用范围 | 是否删本地文件 | 二次确认 |
| --- | --- | --- | --- |
| 右键「删除」 | 当前勾选的任务，含进行中 | 删该任务的临时分片目录；**已合并的成品文件保留** | 有 |
| 工具栏「删除」 | **无视勾选**，仅已完成与已失败 | 删其临时分片目录，成品文件保留 | 无 |
| 工具栏「清空」 | **无视勾选**，已完成 / 已失败 / 已取消 | 不删任何文件 | 有 |

- 删除会中断进行中的下载、清掉临时分片目录，且**不可恢复**：重启后也不会再续传。
  唯一不受影响的是 `output_directory` 下已合并的成品文件。
- 工具栏「删除」的名字容易让人以为它作用于选中项，但实现上不看勾选，只清已完成与已失败的任务。
  要删除指定的任务请用右键菜单。
- 被工具栏两个入口移除的未完成任务会被打上标记，重启后不再自动续传。
