# 2026-08-31 工作日志

## 浅色主题白字 bug 修复

**现象**：浅色背景下，新建任务窗口选中 tab、以及「运行日志」标题是白色字看不清。

**根因**：`src/app/theme.rs` 里 `widgets.active.fg_stroke = WHITE` 的全局设置。
egui 的 `strong_text_color()` 直接取 `widgets.active.text_color()`（见 egui-0.29.1 `style.rs` 的
`strong_text_color` 实现），所以所有 `strong` 文本（运行日志、选中 tab、任务表头、
设置分组标题）在浅色主题下全变成白字——白卡片上看不清。

**修复**（2 个文件）：
1. `theme.rs`：删除 `widgets.active.bg_fill = palette.accent` 和
   `widgets.active.fg_stroke = WHITE` 两行，active 态恢复 egui 默认
   （light=深字深底、dark=白字深底）。需要强调色背景的按钮（primary/danger）
   都显式设置了 `.fill()` 与文字颜色，不依赖该全局设置，删除无影响。
2. `forms.rs`：选中 tab 文字改为 `RichText::strong().color(accent)`，
   与底部下划线同色，选中态更明确。

**验证**：cargo fmt / cargo check / cargo test（58 个全过）。
注：本轮又遇到一次 Windows 文件锁错误（os error 5），无残留进程，重试即恢复。

**教训**：不要在 theme.rs 全局改 `widgets.active.fg_stroke` 来给按钮配白字——
它同时是 `strong_text_color()` 的数据源，会误伤所有加粗文本。按钮文字颜色应在
按钮组件里显式设置（本项目 primary/danger/outline/accent 按钮均已这么做）。

## UI 颜色审查：accent 与 selection 语义分离 + Toast 对比度

白字 bug 之后全面过了一遍界面硬编码颜色，又发现两个对比度问题，已修复：

1. **文本选中看不清**：egui 绘制文本选中时只垫 `selection.bg_fill` 背景矩形、不改文字颜色
   （egui-0.29.1 `text_selection/visuals.rs` 的 `paint_text_selection`）。而 `selection.bg_fill`
   被设成深蓝强调色，浅色主题下深色文字落在深蓝底上看不清选中范围。
   修复：`theme.rs` 新增 `accent_color(dark_mode)` 统一取强调色，6 处读取
   `ui.visuals().selection.bg_fill` 的地方（forms 选中 tab、widgets 三个按钮、
   task_list 选中行背景+文件名超链接）全部改用它；`selection.bg_fill/stroke`
   恢复 egui 默认（浅色=淡蓝底、暗色=深蓝底）。
2. **Toast 标题对比度不足**：固定红 (214,69,65)/绿 (46,160,96) 在暗色底约 2.9–3.8:1、
   亮色下绿字约 3.3:1，不达 WCAG 4.5:1。改为 `theme::status_color(dark, Failed/Completed)`
   （亮色 Failed (214,69,65) 4.6:1 / Completed (21,115,71) 6.3:1；暗色分别 5.7:1 / 7.5:1）。

验证：fmt / check / 58 测试 / clippy -D warnings 全过。

**结论**：`visuals.selection.bg_fill` 不要当强调色用——它是文本选中高亮背景，语义不同。
强调色统一走 `theme::accent_color()`。
